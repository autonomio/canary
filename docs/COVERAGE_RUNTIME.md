# Coverage-guided question research

The native operator path uses one stateful **Sol 6.1 / xhigh** research session and fresh **Sol 6.1 / xhigh** independent audit sessions. Neither scientific session may delegate. Coverage-guided selection is the default: choose question-relevant source batches by the information they add across the typed plan's comparison, outcome, population and condition aspects, including adverse and null findings.

The same audit records a separate per-claim `uncertainty_review`: recommended low/moderate/high (or null when unassessed), reason, fresh evidence IDs and a proposed same-proposition/scope prior match. The API findings, claim inspector, Markdown report and Resolvent metadata preserve this alongside the writer's unchanged grade. Ordinal increased/decreased/unchanged comparisons require the prior ID and recorded grade to match the supplied snapshot; semantic equivalence remains the auditor's proposal. Missing legacy reviews and unverifiable comparisons stay explicit. Source counts, a supported audit or model agreement do not establish independent evidence. No extra model session is added.

Resolvent export keeps its minimum-medium evidence-independence safeguard and maps the recommendation's evidence IDs to destination candidate IDs while retaining the originals. Its handoff requires an explicit accept/override/defer decision; a matched canonical claim needs recorded destination reassessment. Recommendations alone never mutate a world model. Consumer implementation is tracked in [Resolvent #33](https://github.com/autonomio/resolvent/issues/33).

Freshness remains a **review horizon**. `scheduled` records a review date; `event_driven` records reassessment triggers; `historical` needs no scheduled expiry for a bounded observation; `unknown` records no defensible horizon. `as_of` is the source's date, not the agent's review timestamp. The audit flags unsupported freshness metadata and due horizons in its existing findings. A passed date does not invalidate a claim, decay uncertainty, launch research or change Resolvent valid time. Automated expiry actions are separate scope.

```sh
canary ask "Your question" --out out/questions/new-question
# Dashboard launches the fixed script with OUT supplied by its supervisor:
OUT=out/questions/new-question bash scripts/coverage_run.sh ask "Your question"
```

`canary ask` is the default question path and exports the source graph for the dashboard. Legacy review/cycle commands remain separate. When UI and engine use different checkouts, set `CANARY_QUESTION_ENGINE_ROOT` on the dashboard; clean checkouts use their own root.

The workspace must be new. The researcher writes a typed `question-plan.json`, runs full-text-inclusive OpenAlex discovery, screens titles/abstracts, chooses batches, and reads the acquired full sources in the same session. The plan uses **concepts**, not entities. Typed rich plans retain population, efficiency denominators, eligibility and coverage facets; no fields are discarded. OpenAlex `search=` includes indexed full text, titles and abstracts; it is not a body-only search and coverage depends on provider indexing.

Code owns network discovery, public-copy resolution, concurrent download, text extraction, immutable source paragraphs, reproducible quote placement, hash/graph checks, timestamps and usage reconciliation. It does not make semantic selection decisions or author scientific findings. Only selected batches are downloaded; sources become available as individual receipts commit, without waiting for a whole corpus.

Public-copy validation passes its extracted text, page count and blank-page list directly to acquisition; the winning copy is not converted again. Acquisition receipts record `validated_text_reused`. Original bytes, text normalization, page markers and passage offsets follow the same existing path. The extracted result exists only with that copy during acquisition, with no persistent body cache.

PDF parsing uses one shared conversion slot per service data directory, including the native `pdftotext` path, Python fallback and PDF identity checks. Downloads remain concurrent. The API passes its data directory to every tool worker; an OS file lock coordinates separate processes and threads. Native converters inherit the lock descriptor so a parent crash cannot release capacity while its converter still runs. Process exit releases ownership; no lock cleanup daemon is needed. The zero-byte `runtime/pdf-conversion.lock` file remains in place to preserve lock identity. `/api/status` publishes the extraction engine and capacity scope; the dashboard's service details show the shared slot. This bounds simultaneous PDF parsers, not total server CPU or complete research duration.

The first copy to pass the existing readability, preview and required identity checks stops redundant work for that paper. Alternative copies remain eligible until that point. Queued losers release their downloaded buffers without entering the PDF converter; body streaming checks the same signal between chunks, and redirects/linked-copy attempts check it before further work. Already-running converters finish normally and blocked network reads retain their existing timeout. Superseded copies do not count as unavailable papers. `/api/status` exposes `pdf_extraction.skip_superseded_copies`, also shown in dashboard service details. This stops duplicate processing without changing the selected-paper criteria or certifying the paper's scientific completeness.

The minimum target is **50 substantively reviewed question-relevant publications**. Core comparisons and supporting context are separate; source versions count once and linked experiment reports retain study-family IDs. An inaccessible copy, elapsed time or an unexamined source does not establish scarcity. When genuine scarcity prevents the target, the researcher records assessed exhaustion, follow-up searches and access limits. The report exposes this statement rather than certifying it automatically or padding the corpus.

Standalone deterministic commands (no model call):

```sh
.venv/bin/python scripts/run_coverage_research.py discover --workspace PATH --plan PATH/question-plan.json --pages 5
.venv/bin/python scripts/run_coverage_research.py acquire --workspace PATH --ids W123 W456
.venv/bin/python scripts/run_coverage_research.py catalog --workspace PATH
.venv/bin/python scripts/run_coverage_research.py source --workspace PATH W123 --match "methods|results" --context 2 --limit 8
.venv/bin/python scripts/run_coverage_research.py finalize --workspace PATH
```

`discover` saves fresh responses and cursor progress. Its per-call page limit is explicit; truncated branches remain incomplete and the next call resumes them. Supplemental branches may be added under new query IDs; changing an existing query's text requires a new ID. The operator daily-search count includes successful cursor pages from this runtime and explicitly excludes the gateway and other clients. Selected public body acquisition makes no paid OpenAlex content request. Failed papers receive individual receipts; successful canonical bodies are not overwritten. `--retry-failed` records previous failure receipts when an operator requests another attempt in the same run.

OpenAlex rate-limit pauses are shared across questions in the service data directory, separately for anonymous use and configured API-key use. Adding the operator's authorized key makes subsequent discovery use the configured allowance, without clearing the anonymous deadline or search receipts. Configured keys conservatively share one bucket: replacing a key is not proof of a separate account budget and never resets an existing configured-key pause. A `503` with `Retry-After` pauses both allowances. All applicable pauses use the latest deadline; valid Retry-After seconds/dates remain respected across restarts. No automatic credential rotation or ledger reset occurs.

`DiscoverResult` in `/openapi.json` publishes `openalex_allowance` and typed `OpenAlexBackoff` fields: `scope`, `scope_source`, `reason`, `retry_not_before`, `active` and the delay source. The scientist CLI relays those API fields unchanged; the dashboard shows the reason, allowance and retry time in query progress. No key or key fingerprint is stored in the quota ledger or exposed in these records. Pre-upgrade rows contain no credential provenance: by default they remain `legacy_unknown` / `legacy_scope_unknown`, applying to both allowances until the original deadline. They cannot safely be assumed anonymous.

Consumers can observe that state before starting work, without invoking discovery: `GET /api/sources/openalex/status` (MCP `canary_openalex_status`) returns typed `discovery` (`DiscoveryReadiness`) alongside the existing counts. The API derives the allowance from the service data root's own configuration — clients cannot select a root, allowance or ledger — and recomputes the same effective pause discovery would apply, read-only. `status` is `paused` when that pause is active (with the typed `backoff`, including `retry_not_before_epoch`), `available` when no recorded applicable pause blocks the actual allowance, and `unknown` with an `unknown_reason` when the recorded state cannot be read. A pause recorded for a different allowance never reports the actual allowance as paused. `available` is recorded state only (`basis: recorded_backoff_only`, `probe_request_made: false`): no provider request is made, so it is not a guarantee OpenAlex will accept the next request. No secret, credential identity, ledger reset or allowance fallback is involved; scheduling remains the consumer's decision. The dashboard shows the same readiness next to keyword usage.

After funding or another access change, an operator may explicitly recheck a stale hold with `POST /api/sources/openalex/recheck` (CLI `canary sources openalex-recheck`; deliberately not an MCP tool, so research agents cannot release holds). It accepts no root, allowance or ledger selection. When the actual allowance's own scoped hold is active, at most one probe per minute makes a single-work read on the same route — never a counted keyword search. A successful fresh response deletes only that allowance's scoped hold; a still-limited response records the fresh applicable pause (superseding that allowance's stale deadline, race-guarded); provider-wide and legacy holds are reported as not releasable here and left untouched, as are all usage records. Every accepted request and outcome is append-only audit-recorded with the released deadline where one was released. With no active allowance hold it reports `no_hold` and probes nothing. The typed outcome (`OpenAlexRecheck`) distinguishes released, still paused, cooldown, and unavailable — clicking recheck never by itself claims provider availability.

For a **verified pre-upgrade anonymous pause**, set `CANARY_OPENALEX_LEGACY_BACKOFF_ALLOWANCE=anonymous` in the API service environment or operator data directory's `.env`, alongside `OPENALEX_API_KEY`, then restart the service. This explicitly attributes the old row and permits new configured-key discovery; the old deadline still applies to anonymous requests. Use `configured_key` only when that is the verified historical allowance; do not set an attribution if it is unknown. The API/dashboard label an applicable historical pause `operator_attribution`. No original quota row, search receipt, completed research or recorded gap is rewritten. The setting never changes new scoped records or provider-wide pauses, and removing it restores conservative unknown-scope handling.

Provider reference: [OpenAlex authentication and rate limits](https://help.openalex.org/api/authentication/) describes separate keyless/keyed use and account-budget sharing. Offline tests exercise anonymous-to-key recovery, concurrent same-allowance backoff, key replacement, subprocess restart, legacy deadlines, provider-wide pauses and API/CLI/dashboard disclosure; they make no live-search or research-quality claim.

`papers/` preserves originals; `texts/` contains native `pdftotext -layout` output where available, with the existing reader fallback and explicit PDF page markers. Scanned/unreadable sources fail extraction; unknown glyphs remain visible. Tables retain text layout, but images, figures, mathematical notation and ambiguous tables still require original-source inspection. A retrieved source's status says `requires_source_verification` or `preview_suspected`, never automatic full-paper scientific certification.

The payload stores the full question plan, selection decisions, coverage map, actual reading notes and the chain **prose → claims → evidence → canonical verbatim → references**. Every claim stands alone: one proposition, named study/design, population or system, intervention, comparator, endpoint timing/scale and material conditions. Named products and devices need descriptive system scope in the claim; a project name alone is insufficient. Unknown source details stay unknown. Empirical `reported_finding` records link typed study results; `recommendation` and documentary `source_record` are distinct kinds. Claims carry ordinal uncertainty (low=1, moderate=2, high=3), not calibrated probabilities. Study-result fields cite their supporting spans or remain null. Contradictions, gaps, residue, caveats and justified next questions remain typed.

When the question cannot be researched as asked, for example because the product or measure must be identified first, the researcher returns `investigation.json` with a typed `clarification` (`question`, `reason`) and no findings; otherwise `clarification` is null. The run then ends as `needs_clarification`: nothing is bound or audited, and the [run lifecycle](RUN_LIFECYCLE.md#terminal-outcomes) exposes the question.

Raw `investigation.json` remains unchanged. With `audit.max_correction_rounds` (default 3, nonnegative), flagged claims return to the original researcher as untrusted review data. The researcher re-reads the sources and returns typed revise, withdraw or dispute responses; a compound claim may split with explicit parent/child IDs. Every round rebinds evidence and rechecks the whole current scientific snapshot in a fresh audit, including shared records. This conservative full recheck avoids retaining a verdict after a shared dependency changes. There is no audit duration or stall timeout. The independent audit is separate; checked and unchecked claims and its limits are exposed. Supported requires factual fidelity and the standalone standard. Typed `issue_types` record scope, reference, compound, attribution and numerical/endpoint defects. Every evidence record receives a source-based independence assessment (`independent`, `same_study_family`, `unknown`), with inspected references, passages and study-family basis. Code never infers independence from source counts, URLs or a separate auditor. Missing or invalid checks stay `not_checked`; duplicate/unknown claim IDs cannot certify a claim. A material finding attaches only to the current claims it names; unknown IDs become audit validation issues and never widen it. A material finding naming no current claim is a run-level finding: `verification.run_findings`, the dashboard and connector limitations report it and the run is `partial`, while each claim keeps its own source check. Code binds each verdict to a SHA-256 of the statement and the full shared claim/evidence/source snapshot; edits invalidate it. The dashboard and API expose these records. Research and audit have no duration limit. Actual start/end and any cancellation or failure are recorded; incomplete checks remain explicit. A completed research output or passing mechanical source graph does not certify scientific interpretation. `run.json` reports answer availability separately from audit scope. The final neutral payload contains supported claims only; withheld/withdrawn claims retain their last wording, reasons, evidence, study results and revision history. Evidence and study results used only by withheld or withdrawn claims, or by their dropped links, move to `withheld_evidence` and `withheld_study_results`; contradiction, gap and residue records keep their evidence while they name an active claim or no claim. It reports supported and withheld counts/share, correction rounds and any interruption. Summary prose and active links cannot refer to withheld claims. `rounds/000` preserves original research; `rounds/NNN` records each immutable audit, correction and subject. The retained bundle carries the same history. An audit session that exits nonzero, times out or returns no final structured response is a verification failure: its intermediate audit stays in the round history and no verdict is accepted. A stopped verification keeps only the claims the last completed audit passed, unchanged since; every other claim is withheld, and `verification.stopped` records the phase and round that did not finish and that audit's round (`audit_round`, null when no audit completed). If the stopped session rewrote, removed or added protected inputs, including before it failed or was cancelled, `changed_inputs` lists them and no claim stays active. `coverage-map.json` is put back instead: it is the research's coverage bookkeeping, which no claim, evidence record, source or count reads, and a correction has no typed field for it. When a session rewrites, removes or adds it, as a correction continuing the research thread may, Canary restores the research's version before anything reads it again, so every audit reads the map research recorded. The session's file stays as `rounds/NNN/{kind}-coverage-map.json` with the working sources, and that round's history records `restored_inputs`.

`research-receipt.json`, `audit-receipt.json` and `profile.json` preserve the actual scientific session IDs, CLI version, model/effort, start/end/duration and unique native per-response usage. Cached input and reasoning output are subsets, not added again; unavailable counts remain null. Child-session metadata is checked to verify the no-subagent rule. These receipts exclude the coordinating chat and unrelated account activity.

This is a local **operator CLI** deployment using native Codex authentication and automatic execution approval review with the workspace-write sandbox. Acquisition uses self-contained `coverage_sources.py` public source helpers and selectively reads `OPENALEX_API_KEY` from the operator environment or `.env`; no provider key is handed to a scientific session. It is separate from the legacy DeepSeek container/service: it neither changes that service's model contract nor resets/bypasses its rolling ledger. No model/provider/effort fallback is implemented. The operator entry point requires the Canary checkout and authenticated native Codex CLI; acquisition and extraction have no boundary-service or saved-experiment imports. The restricted legacy worker remains a separate deployment.

Offline contracts use synthetic bodies and native receipt fixtures. They test batching, failure containment, canonical provenance and accounting, not scientific quality or live provider throughput. Real research is documented with its own fresh receipts and independent audit.


Before audit, `claim_review_checks` records missing typed study results for empirical `reported_finding` claims (a structural failure), possible unresolved references, and possible repeated propositions sharing the same source and typed value/context fields. The last two are review cues only: code neither rejects nor merges on wording or numeric similarity. Recommendations and documentary `source_record` claims do not require fabricated empirical results. These checks are visible through the research API, CLI/MCP findings and dashboard. No number-presence heuristic is used.


Scientific execution uses API-owned, once-only phase/round leases. Corrections resume the recorded research thread (shared server: unarchive/resume; native fallback: `codex exec resume`), retaining its fixed model, effort and configuration isolation. Audits always start new threads. Native continuation receipts count only new response IDs; `thread_usage` preserves the cumulative thread record without adding earlier turns twice. During audit/correction, source tools are read-only: `discover`, `acquire` and `finalize` are refused with a message naming the phase, also after a progress export has recorded the phase as `runtime_status`. Protected scientific inputs are checked for mutation. A correction response that fails the checks verification applies goes back to the same session once, with every problem named (claim IDs, unknown passage IDs); the rejected response stays as `correction-rejected-response.json` and the receipt records `response_retry`. A response still invalid after that fails the round. No automatic model or backend substitution is allowed.


New investigations include source-bound `claim_links` (`dependency`/`coupling`) and evidence `premise_claim_ids`. A dependency points from prerequisite to dependent claim. The final graph recursively withholds dependents of uncleared premises; coupling does not manufacture a logical premise. Removed evidence/claim links remain in the audit basis and revision history. Typed study-result fields retain their exact canonical verbatim passages as well as IDs. The v4 consumer adapter maps these recorded facts without performing research or admitting them to a world model.

Each round has a logical, hash-checked artifact in `history_manifest`, accessible through `GET /api/runs/{key}/revisions/{round}/{kind}`, CLI `canary bundle RUN_KEY --round N --phase KIND`, and MCP `canary_revision`. Original JSON bytes, raw and normalized audits, source context and revision lineage survive compact retention. Live views explicitly label candidate findings provisional while corrections are underway. These records make audit/correction components inspectable without rerunning discovery or the whole research process; replaying full-paper scientific judgments still requires the original full-source bytes.


A failed or cancelled scientific verification records its attempted round, failure, saved response/checkpoint and terminal native receipt. Completed round receipts reconcile the dashboard to a stopped phase even if no final model response arrived. Correction turns save their complete typed response before returning it. On operational verification failure, full working papers are kept; nothing from the interrupted correction is accepted, and the claims the last completed audit passed stay active. Normal completed reviews, including bounded unresolved/withdrawn outcomes, retain the compact bundle as before. Provider connection failures are separate from the absence of a research/audit time cap.

Run-level accounting issues (including deduplicated publication records and an unmet paper target) remain visible without invalidating source-supported claims. Shared source/hash/graph failures still block every claim; a claim's own record failures (unknown evidence or result IDs, missing evidence, freshness, uncertainty class/score mismatch, a missing linked study result) withhold only that claim. Audit and correction input protection checks additions as well as edits and deletions. Duplicate scientific IDs produce inspectable withheld records rather than leaving provisional claims active. Rejected responses and terminal receipts remain in the hash-addressed round history; operational verification failure keeps full working sources.
